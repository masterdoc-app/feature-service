# Роль Заявитель (`requester`) — design

**Дата:** 2026-08-01  
**Статус:** approved (диалог)  
**Сервис:** feature-service  
**Связано:** фича `tickets`, экран `TicketsScreen` в client-app

## Проблема

Фича `tickets` («Заявки») есть в каталоге и в клиенте (подача своих заявок), но ни одна дефолтная продуктная роль её не получает. Нужна явная роль для сотрудников площадки, которые только создают заявки.

## Решение

Добавить фиксированную продуктную роль:

| roleId | titleRu | features (default) |
|--------|---------|--------------------|
| `requester` | Заявитель | `tickets` |

Полный набор ролей после изменения:

| roleId | titleRu | features (default) |
|--------|---------|--------------------|
| `admin` | Админ | `admin`, `black_box`, `equipment` |
| `dispatcher` | Диспетчер | `map`, `board`, `ai`, `charts` |
| `engineer` | Инженер | `engineer` |
| `manager` | Менеджер | `reports` |
| `requester` | Заявитель | `tickets` |

## Поведение

1. **Новые org** — при первом `GET /roles` сидятся все пять ролей (включая `requester`).
2. **Существующие org** — если в `product_roles` уже есть строки, но нет `requester`, при `GET /roles` (и любом пути через `listWithSeed`) роль **досеивается** с дефолтом `tickets`. Остальные роли не трогаем.
3. **PUT `/roles/requester`** — как у остальных: можно менять `titleRu` и `features` (непустой список, только id из `FeatureCatalog`).
4. **Клиент** — при наличии `tickets` в `/me` открывается экран «Заявки»; `profile` по-прежнему добавляется клиентом всем. Новых экранов и фич в каталоге не добавляем.
5. **Gateway / admin UI** — проксируют `/admin/roles` без хардкода списка ролей; после досева роль появится в списке автоматически.

## Out of scope

- Запрет выдавать `tickets` другим ролям.
- Новые UI для подачи заявок.
- Миграция пользователей / массовое назначение роли в Zitadel.
- Переименование `manager` ↔ `reporter` из старых доков.

## Тесты

- Пустая org: `GET /roles` → 5 ролей, среди них `requester` с `["tickets"]`.
- Org с уже засиденными 4 ролями (без `requester`): повторный `GET /roles` → появляется `requester`, старые роли без изменений.
- `PUT /roles/requester` с валидными фичами → 200; неизвестный feature → 400.
